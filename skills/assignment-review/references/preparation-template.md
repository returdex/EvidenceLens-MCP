# 用户 HD 准备提示词模板

模板 ID：HD-PREP-01。依据已核对的用户课程作业提示词《Assignment HD 完成流程提示词模板》的“阶段 1”，提炼为可复用规则。原用户消息与来源清单保存在本机私有档案，不把课程聊天、截图、附件或私人路径打包进 Skill。本模板是用户工作偏好，不是课程要求，也不证明任何成绩。

## 选择并保留原提示词

当前任务明确提供的提示词优先；其次沿用该任务基线中已登记且仍有效的提示词；未提供时，preparation 使用本模板并说明 `HD-PREP-01`。不把“本轮没有重新粘贴”当作“从未提供”，不在普通审阅中自动搜索其他课程聊天。有多个适用模板时，先保留可兼容条款；无法同时执行的冲突才需要聚焦澄清。新材料只更新受影响的计划。

将已选原提示词拆为有语义的条款，逐项登记“保留／按任务调整／当前不适用／无法据实执行”，写明理由及生成提示词中的落点。不得只写“保留语言和格式”便跳过分析任务、深度、流程和证据要求。无法取得原文时明确未核验，用本模板开展可做部分；不要声称原提示词已经完整复用。用户明确缩小范围时遵循，并说明本轮不覆盖的条款。

六节是提示词的包装结构；下列五项任务写入第 4 节，第 5 节要求分别交付它们。不能以六节结构、JSON 输出、完整报告文件或多个模型替代任务内容。两位审阅者得到相同任务条款；模型输出没有逐项回应时，宿主交接保留该缺口，不能靠综合摘要宣称完成。

## 共同行为偏好

- 不编造要求、数据、结果、引用或教师说明。建议说明对应的要求／criterion；无明文要求的改进标 advice，不伪装为必做。
- 作业说明、rubric、提交说明、tutor clarification 有冲突时，列双方原文、适用范围、版本／日期与当前依据；无法确认优先级则保留争议，不假定某类文件总是优先。
- 缺材料时给具体缺失清单，同时推进已有证据支持的分析和 best-effort 计划。未提供当前稿的完成度是 unknown。
- 目标尽可能接近最高档，判断 realistic；不把“能运行”、功能存在或某项许可等同于最高档，不承诺 HD。
- 中文、结构清晰，优先表格和 checklist；保持用户当前有效格式。后续材料并入现有计划，不重置全部工作。
- report 需要学术、清晰的表达；准备阶段给有依据的结构和内容／证据规划，未要求 report 则不凭空新增交付物。
- 完整可运行代码／完整文件是后续明确授权实现时的偏好；准备阶段规划实现及验证，不直接写最终作业，不因原模板提到代码便扩大编辑权限。
- 有数据分析任务时规划清洗、EDA、图表选择与结论如何支持 rubric；实际任务明确无需清洗或没有数据分析时说明不适用，不强行新增步骤。

## 任务 1：提取官方要求

解释作业主题、目标和需要证明的能力；列出实际交付物、文件格式／命名、字数／页数、时长、截止与提交渠道，以及代码、report、presentation/demo、Git、appendix、AI acknowledgement 等是否适用。每项给来源定位和核验方式。明确必做、rubric 期待、用户偏好、可选改进和未知；不要把列举的交付物全当成该作业必须提交。

## 任务 2：逐条拆解 rubric

逐 criterion 保留原要求、各实际档位及限定语，转成具体任务与 checklist。表中包括：来源／criterion、实际档位差别、达到最高档需要的表现与证据、易失分点／反例、验证方法。只有读到权重和分值时才使用；材料未列 Pass/Credit/Distinction/HD 或档位边界不清时按实际标签／unknown 展示，不补造等级。

每个 criterion 都说明“可能阻止进入最高档的条件”，或注明当前来源中未找到；无稿时这是待核验风险，不是已发生缺陷。区分明文评分条件和专业判断建议。许可某技术路线不等于最高档质量证据，不能先替实现找理由再省略风险。

## 任务 3：从零到提交的 workflow

给逐步计划：每步做什么、输入／前置条件、产出物、对应要求、完成后的验收证据。指出可并行步骤和必须等数据、代码、实验结果或决定完成的依赖；已有进展从当前状态继续。规划早期及中期的 rubric／最高档检查、修正时间和最终提交核验；个人建议日期不能冒充官方期限。准备计划不等于这些操作已经执行。

## 任务 4：下一批需要提供的材料

按当前任务列真正需要的代码、数据、PDF／评分表、运行结果、截图、报错、tutor 回复或草稿；说明每项用于解决什么问题、影响哪些 criterion／步骤、什么格式或范围足够、何时需要。区分现在可补、后续才产生、可选和当前不适用；不要求用户上传不必要的整段私聊或全部文件。缺教师说明或解答稿仍可准备。

## 任务 5：最高档策略

依据实际 rubric 给最关键的 3–5 个着力点；若来源支持不足就只给有依据的项。指出哪些地方除运行结果外还需设计理由、比较、反例、局限，哪些需图表、benchmark、截图、实验或引用。需要 report 时按 rubric 规划章节和每节证据；无 report 时映射到实际交付物，如 Quiz／视频／demo。策略标为建议，区分其来源依据和仍待验证的判断，不许诺分数。

## 交付核对

实际 preparation 报告分别交付五项任务、原提示词条款映射、缺口／冲突及首个可执行步骤；存在适用任务缺失时明示。JSON 模式不增加字段：各任务分析和条款覆盖可以通过多个 findings 的完整 claim/action 表达，来源仍使用真实已捕获摘录，limitations 保留未回应或不可核验范围。宿主按任务组织完整报告，保留 run-local 发现归属；不能只有摘要或只展示内部 JSON。
