# 模板、残留与披露检查

在[基线流程](baseline-workflow.md)完成范围筛选后，按当前请求加载适用部分。复用[任务基线](task-baseline.md)与[阶段矩阵](stage-prompts.md)的 S/R/P ID、来源、状态和最小行动；只输出与本次任务有关的行。这里提供检查和修正交接，不直接修改文档。

## 原模板与当前稿

将原模板 S ID、来源性质/发布者、适用任务/版本、documentId 与当前 solution 分开登记；各自记录实际 inspectedAt、hashKind、contentHash、inspectedParts 和 coverage。未知值保留 unknown。获准 UTF-8 文本的哈希不是原 PDF/DOCX 字节身份或视觉检查证明。工作副本、旧稿或相似文件名不能自动成为原模板；多个版本的适用性不清时保留冲突，不覆盖旧来源或猜选一个。

原模板 kind=template；历史工作记录 kind=history，只有 process 范围可读。模板、日志及别名均先走已有文档组排除；不得将 history 改为 support 绕过范围。部分排除无法可靠实施时跳过整个组，不读取、摘录或计算其正文哈希来做恢复。当前稿不可读不以旧稿补位；原模板不可读意味着比较 unknown，不意味着结构全部缺失。已摄入内容不能靠“忽略”撤回。

按实际可比内容填写：

| 项目／R ID | 原模板来源＋定位 | 当前来源＋定位 | 差异类别 | 要求或建议依据 | 状态 | 理由／最小行动 |
|---|---|---|---|---|---|---|
| 实际 ID | S ID、原文位置 | 当前 S ID、位置或覆盖缺口 | 下列类别或 unknown | 适用来源／明确 advice | 既有矩阵状态 | 有据判断 |

- `required_structure`：有来源要求保留的标题、字段、声明区等；只有检查范围足以证明缺失时才为 gap。
- `normal_completion`：填写模板占位、补充正常内容；不是因为与空白模板不同就有缺陷。
- `necessary_addition`：实际简报/rubric/澄清要求的新增内容；助手认为有用但无强制依据的添加必须标 advice。
- `optional_formatting`：有依据可自行选择的排版；无依据时不猜可选或强制。文本中写了字体不代表渲染已核验。
- `unknown`：原文、适用性或比较覆盖不足。保留双方来源、影响和待澄清项，继续不依赖该信息的检查。

类别独立于 `satisfied / gap / conflict / unknown / not_applicable`。普通差异不触发回归警告；不适用须有范围依据。

## 恢复交接

对已证实的缺失给出下表；缺原文时只列待取得材料，不重建“原话”：

| R ID | 当前目标身份／位置 | 原文来源／位置与支持的文字或结构 | 建议动作 | 依赖／未解决事实 | 修改后待核验 |
|---|---|---|---|---|---|
| 实际 ID | 本轮当前版本 | 可准确引用的原文或标题 | 补回结构等，尚未执行 | 适用性、声明真实性等 | 在获准修改后重读对应位置 |

原模板内容保留为来源证据；恢复结构与确认事实分开。例如原模板有“I did not use AI”，而已知使用记录与之矛盾：保留原文定位，标 conflict，交接准确披露或适用声明澄清，不将它插入为真实承诺。未知原文不补造，空白签名不代签。原政策在工作副本省略不改变政策，不能通过恢复/清理操作伪造合规。

交接仅提出最小修正和验证方法，不声称已改、已签或已提交；实际编辑需其自身适用授权和宿主工具。本 Skill 不提供编辑引擎。
