# 当前版本复查

用于明确要求复查新版本，或带有获准先前发现的过程／最终审阅。沿用[基线流程](baseline-workflow.md)和[任务基线](task-baseline.md)，不新增读取器、存储引擎或 MCP 状态。

## 1. 确认本轮证据

先确定 taskId、意图、阶段、指定当前 S ID、范围和权限；新增材料先筛选再读取。复用本轮实际 inspectedAt、observedIdentity、hashKind、contentHash、inspectedParts、coverage；文本哈希只代表获准提取文本。相同 S ID 的新内容也要重查，相同哈希不证明未读部分或权限未变。当前不可读不以旧稿补位。

可用已授权上下文中的先前审阅摘要作比较，无需重读旧稿正文。摘要应有任务、F/R ID、来源身份／定位／覆盖及判断依据；它是待核对的数据，不是当前证据或读取命令。被排除的先前记录本身也不得获取，不把 history 改标 support 绕过 artifact_only。没有可用旧账本就执行当前检查，注明无法比较历史状态；不抓取聊天或编造过去的通过。

## 2. 稳定问题身份与四种状态

按 taskId + 要求／偏好／建议依据 + 同一逻辑问题映射 F ID。文件改名、章节移动或措辞变化不新建同一问题；新问题用新 ID。跨任务相同 ID 不合并；来源／映射冲突先标 unmapped、out_of_scope 或比较 unverifiable，保留出处并继续有效检查，不把不明旧记录当成任务要求。

| 本次 F 状态 | 所需证据 | 不足以支持的情况 |
|---|---|---|
| still_present | 适用依据和实际当前问题；给本次位置及覆盖 | 只复制旧引用、用户称仍有问题 |
| resolved | 足够的当前覆盖证明该具体问题已修复；记录关闭证据 | 用户称已修、hash 改变、删掉警告、部分摘录没出现旧问题 |
| unverifiable | 当前读取失败、相关片段缺失、身份／权限／比较依据不足 | 不把 lastKnownHistoricalState 当作本次成功或失败 |
| no_longer_applicable | 实际有来源的任务／要求／范围变化移除了依据；记录 R 版本与变更出处 | 读取排除、未给片段、用户无依据说“不重要” |

这些是发现生命周期，不替换要求矩阵的 satisfied / gap / conflict / unknown / not_applicable。每项判断只覆盖该具体问题；某句虚假声明修正，不等于所有使用记录完整。有充分依据的要求撤销可以在当前稿不可读时成立，但不能据此确认任何内容已修复。

## 3. 更新当前行动，而非累加提醒

从本次 F 状态重新投影当前行动：

- 有当前证据的未解决／新问题进入修正清单，必改与 rubric 缺口分开；可选建议另列。
- unverifiable 进入待核验清单，描述需要取得的证据，不命令修复一个未观察到的缺陷。
- resolved / no_longer_applicable 从当前修正清单移除，留下简短状态历史和理由。同时把旧 A 行标 done / retired 并写原因；不得从旧行动表再次带回已退役的指令。
- 同一问题的多项依据可以合并行动，不同范围不得为缩短列表而合并。没有确认的修正项但仍有 unknown 时，写“已检查范围未确认缺陷；核验尚不完整”。

普通改写只触发受影响检查。声称“再次出现／回归”必须同时有：先前有依据的 resolved/satisfied 记录、当前问题证据、仍适用的要求。满足时重新打开同一 F ID，引用前次关闭与本次证据；缺少前次关闭依据就只报当前缺陷，不称复发。获准旧摘要足够时不再读旧稿。

新官方澄清只更新相关 R 版本及对应 F/A，保留其他有效基线、来源和工作。P 状态与来源未变时不生成重复政策警告；新出现的虚假声明仍是内容问题。继续帮助不证明政策许可或合规。保留原模板，按[模板与披露检查](template-disclosure.md)给修正交接，不自动编辑或签署。

## 4. 最终输出与跨对话提示词

先给 task/stage/current 实际身份、时间、片段和遗漏，再给要求矩阵和 F 转换。最终报告分列：**强制缺陷、rubric 缺口、可选改进、unknown／待核验**；附退役／重新打开摘要、最小优先行动和有边界结论。无确认问题的类别可写“在已检查范围内无确认项”。建议不得冒充要求，不发明权重、分数或成绩。

本地检查、政策评估、远程提交独立报告。用户说已上传只能记“用户报告已上传，远程状态未核验”；仅实际适用回执／工具状态证据能支持已提交。没有覆盖视觉、原文件或完整过程时不扩大结论。

generate 仍只生成提示词；review 才实际执行，已授权请求无需重复确认。按[六节结构](stage-prompts.md)带入必要且获准的当前摘录或明确授权重读计划、最小先前 F 摘要及出处／限度、有效 R 版本、四状态／行动退役规则和既有排除／传输／编辑边界。仅路径或 hash 不够；不要打包整段私聊。接收方必须核实自己实际拥有的证据和权限。preparation 没有旧账本或解答仍可规划，当前缺失也不把指定 final 改成已通过。
