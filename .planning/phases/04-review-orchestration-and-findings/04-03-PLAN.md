<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| MCP client → `handleReviewRequest` | Untrusted requests can attempt invalid roles, content combinations, forged provenance, oversized payloads, and filesystem access. |
| server → filesystem normalization | Evidence crosses into the existing Phase 3 allowlisted read-only boundary. |
| analyzer → MCP response | Derived findings and citations become client-visible and must not disclose raw content or unauthorized paths. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-04-11 | Elevation of Privilege | role-validation ordering | mitigate | Validate complete/unique roles before normalization so invalid requests cannot trigger filesystem reads or analysis side effects. |
| T-04-12 | Tampering | duplicate evidence-id gate | mitigate | Apply strict request-schema duplicate detection before role validation, normalization, or filesystem reads; map it to stable INVALID_REQUEST. |
| T-04-13 | Information Disclosure | MCP response/error paths | mitigate | Reuse strict schemas and `toToolErrorResult`; preserve logical filesystem URIs only and exclude raw content, transient bytes, absolute roots, secrets, and stacks. |
| T-04-14 | Tampering | handler → analyzer/citation resolver | mitigate | Pass normalized evidence and transient analysis pairing from the authorized dispatcher; reject caller-invented citations and validate the final response schema. |
| T-04-15 | Denial of Service | MCP orchestration | mitigate | Preserve Phase 2/3 evidence/item/byte/parser caps and add bounded finding/citation/aggregate-transient-analysis limits before deterministic comparison. |
| T-04-16 | Elevation of Privilege | MCP tool registry/analyzer | mitigate | Keep one `review_evidence` tool with `readOnlyHint:true`, `destructiveHint:false`, `idempotentHint:true`; analyzer receives no path/read adapter and performs no provider/network/Docker/process/mutation operations. |
| T-04-17 | Repudiation | response metadata and deterministic output | mitigate | Preserve requestId mapping, fixed generatedAt, server version 0.1.2, deterministic analyzerName/analyzerVersion, stable unique finding ids/order, hashes, and typed citations. |
</threat_model>
