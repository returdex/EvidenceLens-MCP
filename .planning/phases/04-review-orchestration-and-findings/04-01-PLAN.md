<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| MCP/client → review contract | Untrusted role, citation, finding-shaped, and evidence metadata crosses the request/response schema boundary. |
| normalized evidence → finding citation | Internal provenance must be referenced without allowing caller-supplied paths or hashes to become authoritative. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-04-01 | Spoofing | `src/review/roles.ts` | mitigate | Require exactly one validated item for each required role; sort missing/duplicate diagnostics deterministically. |
| T-04-02 | Tampering | `reviewCitationSchema` | mitigate | Reuse strict normalized reference/hash schemas and require typed citation fields; reject unknown fields and arbitrary paths. |
| T-04-03 | Information Disclosure | stable error serialization | mitigate | Emit only `INVALID_REVIEW_ROLES` and its fixed generic message; never serialize ids, references, content, or filesystem roots. |
| T-04-04 | Denial of Service | finding/observation arrays and strings | mitigate | Apply bounded ids, text, citation, follow-up, and observation lengths through strict Zod schemas. |
| T-04-05 | Repudiation | finding ids and citations | mitigate | Require stable identifiers, content hashes, typed locations, and deterministic response metadata for every finding. |
</threat_model>
