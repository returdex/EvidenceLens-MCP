The previous plan exports strict `ReviewFinding`, `ReviewCitation`, and `ReviewObservation` contracts. Existing normalizers return only `NormalizedEvidence` metadata/references/visual payloads; they do not return extracted text. `normalizeEvidenceItems(items, {filesystemPolicy, filesystemReadAdapter, generatedAt})` remains the sole authorized path for filesystem-backed normalization, but Phase 4 adds an internal paired result (for example `NormalizedEvidenceBundle`) containing `normalizedEvidence` plus `analysisPayloads`. The payload type is internal-only: `{ evidenceId, role, type, reference, text?, tableCells?, bytes?, byteLength }`, with text/table text and bytes bounded by existing per-type limits and an explicit aggregate analysis-memory cap; it is created from the already-authorized inline bytes or filesystem read bytes, passed directly to the analyzer, never serialized into `ReviewResponse`, never stored after the handler returns, and never used to reopen a filesystem path. PDF/image bytes are available only transiently for deterministic metadata/visual-state handling; no provider/model call is made in this plan.
