<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| MCP caller -> schema/dispatcher | Untrusted source selection and content enter strict validation and one bounded dispatch path. |
| Server configuration -> policy | Only explicit root ids are available; no implicit root is selected. |
| Normalized evidence/errors -> client | Safe provenance is preserved while OS paths, secrets, stacks, and unrelated details are suppressed. |
| Tool registry -> caller | Registry remains a single read-only evidence tool. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-03-13 | Elevation of Privilege | dispatcher | mitigate | Filesystem sources require injected policy and bounded reader; `reference` never grants permission. |
| T-03-14 | Information Disclosure | provenance | mitigate | Use filesystem URI plus existing hashes/references/metadata; never expose absolute roots. |
| T-03-15 | Information Disclosure | errors | mitigate | Stable sanitized codes/messages suppress paths, secrets, stacks, and environment values. |
| T-03-16 | Repudiation | response | mitigate | Preserve request/source ids, safe reference, hashes, typed locations, extraction metadata, warnings, and deterministic metadata. |
| T-03-17 | Elevation of Privilege | server config | mitigate | Explicit `allowedRoots`/env only; unset config has no filesystem fallback. |
| T-03-18 | Denial of Service | filesystem requests | mitigate | Reuse Phase 2 item/type byte limits; no directory indexing; reject before parser fan-out. |
| T-03-19 | Tampering | tool surface | mitigate | Keep read-only/destructive-false annotations and scan for mutation/provider operations. |
</threat_model>
