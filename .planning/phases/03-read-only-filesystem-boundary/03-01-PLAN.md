<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| MCP request -> Zod source schema | Untrusted root id and relative path enter strict validation. |
| Configured roots -> canonical policy | Operator directories become trusted roots only after canonicalization. |
| Policy -> future reader | Only an authorized canonical target and sanitized logical reference may cross. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-03-01 | Elevation of Privilege | filesystem source schema | mitigate | Require root id/relative path, reject ambiguity and unsafe path syntax, keep `reference` opaque. |
| T-03-02 | Information Disclosure | policy provenance | mitigate | Emit `filesystem://root-id/relative-path`, never configured absolute roots. |
| T-03-03 | Tampering | containment check | mitigate | Canonicalize roots/candidates and use segment-aware relative containment; test escaping symlinks. |
| T-03-04 | Denial of Service | root configuration | mitigate | Bound ids/paths, reject duplicates, avoid recursive traversal. |
| T-03-05 | Repudiation | root selection | mitigate | Preserve stable root id and normalized relative path for downstream provenance. |
| T-03-06 | Tampering | mutation surface | mitigate | Authorization-only API and source scan forbid mutation operations. |
</threat_model>
