<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| normalized evidence -> outbound DeepSeek request | Evidence text and retained visual bytes leave the local process. |
| config -> fetch | Base URL, model, timeout, retry settings, and API key control outbound calls. |
| DeepSeek response -> local validator | External JSON attempts to produce findings/citations. |
| network failure -> retry loop | Remote behavior can trigger repeated work or resource exhaustion. |
| adapter result -> later MCP wiring | Provider metadata and findings must remain attributable and contract-safe. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-05-07 | Information Disclosure | `deepseek.ts` serializer | mitigate | Send only bounded DTO fields, use inline data URLs, exclude paths/read adapters/secrets, and assert absence in transport tests. |
| T-05-08 | Tampering | `deepseek.ts` parser | mitigate | Require JSON Output, strict draft schema, normalized citation resolution, and `PROVIDER_INVALID_RESPONSE` on mismatch; never partial-return/fallback. |
| T-05-09 | Denial of Service | `retry.ts` | mitigate | Max two retries, jittered backoff, per-request timeout, total-wait cutoff, and injectable-clock tests. |
| T-05-10 | SSRF | `deepseek.ts` endpoint | mitigate | Consume only validated config; reject unsafe endpoints and construct only fixed `/chat/completions`. |
| T-05-11 | Information Disclosure | HTTP/error handling | mitigate | Never retain or serialize raw bodies, complete URLs, headers, keys, stacks, or model prose in public errors. |
| T-05-12 | Repudiation | provider result | mitigate | Record provider/model/promptVersion/inputFingerprint/request ID and preserve deterministic/model sets separately. |
| T-05-13 | Tampering | MCP/provenance boundary | mitigate | Return only locally validated findings; no public schema changes, deterministic overwrite, or arbitrary loading. |
</threat_model>
