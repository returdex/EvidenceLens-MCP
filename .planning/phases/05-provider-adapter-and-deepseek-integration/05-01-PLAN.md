<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| local config/environment -> provider runtime | Secrets and endpoint/model settings enter the process. |
| normalized evidence -> provider DTO | Sensitive text/table/image bytes cross into an external provider request. |
| provider JSON draft -> local findings | Untrusted model output attempts to become provenance-bearing findings. |
| provider/internal errors -> MCP response | Upstream details could leak through the public error serializer. |
| provider DTO/config -> HTTP adapter | Endpoint and request fields could enable unintended network access. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-05-01 | Information Disclosure | `config.ts`, local config | mitigate | Ignore the secret file, keep example placeholder-only, reject/log no raw config, and test key/URL redaction. |
| T-05-02 | Information Disclosure | `types.ts`, `provenance.ts` | mitigate | DTO excludes paths/adapters/raw MCP input; validation accepts only normalized evidence identities and bounded payloads. |
| T-05-03 | Tampering | `provenance.ts` | mitigate | Strict draft schema plus local ID/role/hash/reference/location/visual checks; malformed output maps to `PROVIDER_INVALID_RESPONSE`. |
| T-05-04 | Denial of Service / SSRF | `config.ts` | mitigate | Bound timeout/retry/total-wait/inference settings, allowlist models, and reject unsafe endpoints before transport creation. |
| T-05-05 | Repudiation | provider result envelope | mitigate | Require provider/model/promptVersion/inputFingerprint fields and separate deterministic/model result sets. |
| T-05-06 | Tampering | MCP contract boundary | mitigate | Keep public request/response schemas untouched and test the provider interface as internal-only. |
</threat_model>
