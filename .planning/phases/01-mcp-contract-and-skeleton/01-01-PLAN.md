<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client -> `review_evidence` tool | Untrusted JSON request enters the server process. |
| Tool contract -> future evidence interface | Metadata today will later reference local paths and external evidence content. |
| Server process -> local runtime | Server can access process environment and filesystem unless implementation avoids it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | Future evidence interface | mitigate | Keep Phase 1 evidence metadata-only and avoid path reads; Plan 02 will add schema rejection for malformed references. |
| T-01-02 | Denial of Service | `review_evidence` input | mitigate | Expose `limits` contract fields now and require Plan 02 validation for max objective length and max evidence count. |
| T-01-03 | Elevation of Privilege | Tool registry | mitigate | Register exactly one read-only review tool; do not expose write/delete/mutation tools or filesystem APIs. |
| T-01-04 | Information Disclosure | Server runtime | mitigate | Handler must not read `process.env`, filesystem contents, or provider credentials; response metadata uses fixed server name/version only. |
| T-01-05 | Malformed Request Handling | Tool handler | mitigate | Plan 01 keeps deterministic output; Plan 02 must replace permissive input with strict Zod validation and machine-readable errors. |
</threat_model>
