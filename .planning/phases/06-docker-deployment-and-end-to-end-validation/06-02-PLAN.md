<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Shell smoke client -> container stdio | Untrusted JSON-RPC input and server output cross the process boundary. |
| Mounted evidence -> normalizer/provider | Fixed fixture paths and bounded content cross the `/workspace` allowlist into analysis. |
| Mock/DeepSeek provider -> public response | Provider output must be schema/provenance validated before MCP serialization. |
| Documentation/user commands -> runtime secrets/network | Human-provided project-local credentials enable the explicitly billable real path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-06-07 | Information Disclosure | smoke diagnostics and missing-key checks | mitigate | Print only phase labels and sanitized stable error objects; assert output excludes API keys, paths, raw fixture text, request details, upstream bodies, and stacks. |
| T-06-08 | Tampering | read-only mount escape | mitigate | Smoke attempts a marker write under `/workspace`, expects failure, and validates exact `filesystem://course/...` references with no host absolute path. |
| T-06-09 | Elevation of Privilege/DoS | Docker smoke process | mitigate | Use Compose’s read-only root/non-root/tmpfs contract from Plan 01, no privileged/network/socket features, bounded fixture requests, cleanup traps, and timeouts/non-zero failure handling. |
| T-06-10 | SSRF/Arbitrary Access | real provider command and evidence descriptors | mitigate | Document only the configured DeepSeek profile and `/workspace` fixture paths; do not add arbitrary endpoints, modules, file uploads, or transports; retain existing typed config bounds. |
| T-06-11 | Tampering/Information Disclosure | malformed provider output | mitigate | Inject a fake provider only through `ReviewProvider`, validate through `reviewToolResultSchema`/`reviewResponseSchema`, require citations to normalized evidence/hashes, and reject malformed output without fallback. |
| T-06-12 | Misleading Success/Repudiation | E2E and live-review assertions | mitigate | Separate offline smoke, mock E2E, and `scripts/docker-review-real.mjs`; require `ok: true`, exact tool/protocol phases, four fixed role mappings, structural citations/hashes/metadata, and clear non-zero failures; never treat deterministic fallback or exact prose as proof of DeepSeek success. |
</threat_model>
