## Concrete existing conventions

- `collectBaselineSources(metadata, readSource)` returns selection/items/unavailable; selected alone does not prove inspection. Current solution is selected by ID; old solutions never replace it, history requires process scope. Reuse this API without extending kind or pretending prior findings are tool authorization.
- task-baseline.md uses `admitted_utf8_text_sha256`, actual parts/coverage and stable S/R/P IDs. Changed bytes require reinspection, not automatic regression. Equal text hash cannot establish identity, coverage or freshness of uninspected content.
- stage-prompts.md has `satisfied / gap / conflict / unknown / not_applicable` for requirement evidence. Recheck lifecycle is a separate dimension; resolved is not a new MCP status or JSON role.
- Policy dedup already uses P ID and supporting evidence. Reuse it alongside, not instead of, content finding updates. A current false declaration remains a content finding.
- Existing cases already cover original identity, contextual residue and disclosure. The new acceptance must connect them across versions, not merely rerun isolated cases and call it end-to-end.

## Minimal verification

Existing node:test gate and prior case shell blocks supply regression. Actual emitted lifecycle matrices/action lists and portable prompt outputs supply inline semantic evidence. No new parser, finding engine, regex scrubber, report platform or dependencies. Local links/frontmatter use the existing narrow validator; source/semantic claims stay separate.
