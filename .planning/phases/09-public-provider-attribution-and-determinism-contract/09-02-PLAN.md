<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Provider implementation → review orchestrator | Untrusted provider return values and thrown values cross into trusted result validation and error classification. |
| Provider findings → public response schema | Provider-controlled IDs and attribution can spoof another provider unless cross-field namespace invariants are enforced. |
| Provider citations → normalized local visual evidence | Provider-controlled visual hashes can tamper with provenance unless bound exactly to retained normalized bytes. |
| Internal provider failure → public MCP error | Native exceptions, malformed objects, messages, and stacks must collapse to one sanitized public classification. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-GC-01 | Spoofing | `reviewResponseSchema` provider attribution | mitigate | Enforce attribution iff provider-prefixed findings exist and require every namespace to equal `metadata.provider.name`; test missing, extraneous, wrong, mixed, and matching states. |
| T-09-GC-02 | Tampering | Image/screenshot provider citations | mitigate | Require `visualPayloadSha256` and compare it exactly with the cited normalized evidence `visualPayload.sha256`; missing/wrong values return sanitized `PROVIDER_FAILURE`. |
| T-09-GC-03 | Information Disclosure | Provider exception/result boundary | mitigate | Parse a strict allowlisted result schema, wrap unknown throws without cause/message copying, and assert sentinels/stacks never serialize. |
| T-09-GC-04 | Repudiation | Provider failure classification | mitigate | Catch at the provider call boundary so TypeError/RangeError/other throws are recorded publicly as `PROVIDER_FAILURE`, never client `INVALID_REQUEST` or `LIMIT_EXCEEDED`. |
| T-09-GC-05 | Tampering | Configured-provider control flow | mitigate | Remove truthiness guards and require successful runtime parsing for every configured-provider return; nullish/incomplete values fail closed as `PROVIDER_INVALID_RESPONSE`. |
| T-09-GC-06 | Denial of Service | Runtime provider-result parsing | mitigate | Cap `modelFindings` and `deterministicFindings` independently at `MAX_PROVIDER_FINDINGS = 100`; test 100-entry acceptance and 101-entry fail-closed behavior before projection. |
| T-09-GC-07 | Elevation of Privilege | Review/provider projection | accept | N/A: this phase adds no identity, permission, execution, filesystem, startup, or provider-configuration capability; strict schemas only reduce data accepted across the existing provider boundary. |
</threat_model>
