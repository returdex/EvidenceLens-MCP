## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Handler options → normalization/lifecycle | Getters are embedder-controlled code; early or repeated access can misclassify failures, bypass cleanup, or make a configured provider disappear. |
| Provider return object → result preflight/Zod | Keys, descriptors, prototypes, and Proxy traps are untrusted and can conceal private data or throw during inspection. |
| Analysis cleanup → retained references | A hostile local setter, frozen array, detached buffer, or similar fault must not stop later sensitive targets from being scrubbed. |
| Runtime behavior → public documentation | Overbroad strict-rejection or incomplete cleanup prose creates a false security contract even when ordinary tests pass. |
