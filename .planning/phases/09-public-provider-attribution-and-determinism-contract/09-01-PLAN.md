```typescript

  analyzerName: string;
  analyzerVersion: string;

```

Existing provider result identity in `src/providers/types.ts`:

```typescript
export interface ProviderReviewResult {
  provider: string;
  model: string;
  promptVersion: string;
  inputFingerprint: string;
  modelFindings: readonly ReviewFinding[];
  deterministicFindings: readonly ReviewFinding[];
}
```

Evolve the public metadata additively as an optional strict child object, preserving all existing required fields and leaving deterministic-only output byte-for-byte unchanged:

```typescript
provider?: {
  name: string;
  model: string;
}
```

`provider` is present if and only if validated provider findings are included. `name` is the existing safe provider slug and `model` is a bounded identifier; no other `ProviderReviewResult`, provider configuration, transport, or prompt field is public.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Provider implementation → review orchestrator | Provider-controlled identity and findings cross into trusted local validation and must not spoof the configured invocation or carry hidden fields into output. |
| Review orchestrator → public MCP JSON | Internal configuration, prompt, fingerprint, transport, and upstream response data must be reduced to the allowlisted provider/model identity. |
| Public findings → normalized evidence provenance | Provider variability must not alter locally authoritative citation roles, source references, hashes, or typed locations. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Spoofing | `ProviderReviewResult.provider` / `.model` | mitigate | In `src/tools/review.ts`, require returned provider name and model to match the invoked provider and request inference before projection; mismatches become sanitized `PROVIDER_FAILURE`. |
| T-09-02 | Tampering | Provider findings and citations | mitigate | Preserve existing finding namespacing, strict `reviewFindingSchema`, and response-level citation/hash/reference/location binding before serialization. |
| T-09-03 | Repudiation | Analyzer attribution and determinism claims | mitigate | Retain deterministic analyzer name/version, emit provider/model only for public provider findings, and test exact offline bytes separately from variable provider outputs. |
| T-09-04 | Information Disclosure | Public response metadata | mitigate | Construct an allowlisted `{name, model}` projection; strict schemas and sentinel tests prohibit keys, endpoints, prompts, fingerprints, envelopes, raw responses, and transport data. |
| T-09-05 | Denial of Service | Attribution identifier parsing | mitigate | Bound provider/model lengths and character sets at the strict response boundary; retain existing finding and response bounds. |
| T-09-06 | Elevation of Privilege | Provider metadata | accept | Attribution is inert response data and grants no filesystem, network, process, or configuration capability; no new executable interpretation is introduced. |
</threat_model>
