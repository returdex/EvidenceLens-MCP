<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller/fixture bytes -> text parser | Untrusted text bytes enter normalization. |
| Caller/fixture bytes -> table parser | Untrusted CSV/TSV/table bytes enter normalization. |
| Normalizer output -> response contract | Extracted references and warnings become client-visible metadata. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Tampering | Text references | mitigate | Generate 1-based line references from parser-controlled splitting, not caller-provided line numbers; tests verify exact line references from fixture content. |
| T-02-08 | Denial of Service | Text/table input size | mitigate | Enforce central byte, row, and column limits in `src/evidence/limits.ts`; tests cover oversized text and table inputs. |
| T-02-09 | Tampering | Table formula/cell-content injection | mitigate | Treat formula-like values as literal strings, never evaluate them, and emit `CELL_FORMULA_LITERAL` warnings verified by tests. |
| T-02-10 | Information Disclosure | Extracted text/table content | mitigate | Normalized metadata must preserve references and warnings without logging or returning unrelated filesystem paths, environment variables, or process details. |
| T-02-11 | Repudiation | Content hash generation | mitigate | Compute SHA-256 from original input bytes/string in a shared helper and test against known digest values. |
| T-02-12 | Denial of Service | Parser dependency behavior | mitigate | If adding a CSV parser package, execution must validate current official API and keep parser limits outside dependency defaults so malformed CSV cannot bypass project caps. |
</threat_model>
