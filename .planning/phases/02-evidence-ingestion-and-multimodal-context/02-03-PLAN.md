<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller/fixture bytes -> PDF parser | Untrusted compressed and structured PDF bytes enter parser libraries. |
| Caller/fixture bytes -> image parser | Untrusted image bytes enter metadata/decoder libraries. |
| PDF/image parser -> visual payload metadata | Binary-derived page/image metadata becomes downstream multimodal context. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-13 | Denial of Service | PDF parser | mitigate | Enforce max PDF bytes and max page count before/while parsing; tests cover oversized and excessive-page cases. |
| T-02-14 | Denial of Service | Image decoder | mitigate | Check byte length and pixel count before retaining visual payloads; reject decompression-bomb dimensions and unsupported MIME types. |
| T-02-15 | Tampering | PDF page references | mitigate | Generate page numbers/page count from parser output, not caller-provided metadata; tests assert page references from known fixtures. |
| T-02-16 | Information Disclosure | Visual payload handling | mitigate | Include bounded base64 payloads only under explicit size caps; for scanned/unextractable PDF pages, fail safely if bounded payload bytes cannot be produced instead of returning metadata-only success. |
| T-02-17 | Repudiation | PDF/image hashes | mitigate | Hash original bytes and visual payload bytes separately where payload bytes are included; tests assert SHA-256 fields. |
| T-02-18 | Information Disclosure | Parser errors | mitigate | Convert parser failures into sanitized warnings or safe errors without raw filesystem paths, environment values, or dependency stack traces. |
| T-02-19 | Denial of Service | Parser dependency behavior | mitigate | Execution must validate current official parser APIs and keep project-enforced caps outside library defaults. |
</threat_model>
