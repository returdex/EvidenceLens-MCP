<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client -> contract parser | Untrusted request metadata enters strict Zod schemas. |
| Parser modules -> response contract | Extracted metadata and warnings are serialized for clients and providers. |
| Visual payload metadata -> downstream model context | Binary-derived metadata must not overstate availability or leak raw data unexpectedly. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `reviewEvidenceInputSchema.reference` | mitigate | Preserve Phase 1 ASCII control-character rejection and keep `reference` opaque; tests must cover null byte/newline rejection so path/reference injection cannot be hidden in metadata. |
| T-02-02 | Denial of Service | `visualPayloadSchema` | mitigate | Represent byte length and dimensions with capped positive integers; reject negative, infinite, or implausibly large metadata values before parser output can enter `ReviewResponse`. |
| T-02-03 | Information Disclosure | `normalizedEvidenceSchema` | mitigate | Require explicit `warnings` and `extraction.partial` metadata so partial/unavailable representations are visible; do not add raw extracted content to the shared response contract in this plan. |
| T-02-04 | Repudiation | `contentHashSchema` and `extractionMetadataSchema` | mitigate | Require SHA-256 hash, extractor name/version, and generated timestamp so artifacts can be traced to parser output. |
| T-02-05 | Spoofing | Source identity fields | mitigate | Require caller evidence `id`, evidence `type`, and original `reference` on every normalized artifact; strict schemas reject missing or mismatched identity. |
| T-02-06 | Information Disclosure | Visual payload descriptors | mitigate | Model visual availability using descriptors and hashes; parser plans must decide when base64 payloads are included and must record warnings when omitted. |
</threat_model>
