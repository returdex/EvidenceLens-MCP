<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client -> review handler | Untrusted request metadata and explicit evidence content enter validation. |
| Review handler -> normalizer dispatcher | Validated evidence items are routed to parser modules. |
| Normalizer dispatcher -> MCP response | Extracted metadata, warnings, and visual payload descriptors are serialized to clients. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-20 | Tampering | Request reference/content fields | mitigate | Validate exact type-specific content fields with Zod: text/table bounded UTF-8 `content`, PDF/image/screenshot canonical bounded `contentBase64`, strict MIME constraints, inconsistent-combination rejection, ASCII control-character rejection, and `reference` never treated as filesystem permission. |
| T-02-21 | Elevation of Privilege | MCP tool registry | mitigate | Keep only `review_evidence` registered with read-only/non-destructive annotations; protocol tests assert no write/delete/mutate tools. |
| T-02-22 | Information Disclosure | Extracted normalized output | mitigate | Return only contract-defined normalized metadata/content snippets if explicitly modeled; sanitize parser errors through existing error helper and avoid raw stack traces or environment values. |
| T-02-23 | Denial of Service | Dispatcher and parser fan-out | mitigate | Preserve max evidence item limits and parser-specific byte/page/row/pixel caps; tests cover limit-exceeded behavior. |
| T-02-24 | Tampering | Formula/cell-content injection | mitigate | Table normalizer warnings must survive through handler response; contract tests assert `CELL_FORMULA_LITERAL` warnings reach `normalizedEvidence`. |
| T-02-25 | Information Disclosure | Visual payload handling | mitigate | Bounded visual payload metadata must survive through the handler; omitted/unavailable payload bytes require warnings in response metadata. |
| T-02-26 | Repudiation | Content provenance | mitigate | Every normalized artifact returned through the MCP tool must include source identity, SHA-256 hash, extractor metadata, and references where available. |
| T-02-27 | Denial of Service | PDF/image/table parser bombs | mitigate | Dispatcher must not bypass parser-level caps; full test suite includes oversized PDF/image/table cases. |
</threat_model>
