## Cross-phase integration

The core offline chain is wired: MCP stdio → request schema → allowlisted filesystem reads → multimodal normalization → deterministic/provider orchestration → local provenance validation. The injected four-fixture E2E and Docker offline runtime both pass.

The remaining blockers are:

1. Public responses discard provider/model attribution required for auditability.
2. The credentialed live test exercises the provider adapter but not the complete MCP/file/public-response path.
3. Non-Docker startup silently swallows invalid provider configuration.
4. Credentialed model variability conflicts with the documented byte-for-byte deterministic response promise.

## Requirements cross-reference

The checklist and traceability table mark 20/20 requirements complete, and plan summaries claim the relevant requirements. Goal-backward integration evidence supports 15/20 without qualification. MCP-02, SAFE-01, SAFE-03, SAFE-04, and PROV-01 require closure work described in the frontmatter gaps.

## Nyquist coverage

No phase has a `*-VALIDATION.md`. This is a validation-coverage warning rather than the source of the four blockers, but the milestone is not Nyquist-compliant.

## Recommended gap closure

1. Add public analyzer/provider attribution without exposing secrets or unstable upstream envelopes.
2. Make provider configuration fail closed consistently across Docker and local startup.
3. Add a credentialed full-boundary MCP E2E path, while keeping it opt-in and structural-only.
4. Scope deterministic guarantees to deterministic/offline findings or make provider variability explicit in the contract.
5. Verify or harden Linux intermediate path no-follow handling and synchronize planning metadata.
